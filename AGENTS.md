# AGENTS.md — saltext-opnsense

Harness-agnostic contract for autonomous coding agents and human contributors.
`CLAUDE.md` and `.cursorrules` are symlinks to this file: edit **only** `AGENTS.md`.

`saltext-opnsense` bridges Salt's declarative, idempotent model with OPNsense's imperative,
UI-driven REST API. Requires `salt>=3008` and Python `>=3.10`. It is **Resources-only**: the proxy
minion was removed in 1.0.0, so do not add proxy code or `salt-proxy` docs.

## 1. Repository overview and architecture map

Layering, bottom to top:

```text
utils/opnsense.py      HTTP client (OPNsenseClient), credential resolution, error mapping
utils/diff.py          GET-vs-POST normalization + diff engine (the idempotency core)
utils/common.py        UUID test, reconfigure-path parsing, kwarg stripping, version gate
resources/opnsense/    Salt Resource connection module (per-resource cached client)
modules/opnsense.py    generic execution module + runtime-injected wrappers (__getattr__)
states/opnsense.py     generic states: item_present / item_absent / items_* / reconfigured
modules/dns.py + states/dns.py   hand-written Unbound alias helpers (opnsense_dns)
```

## 2. Code-generation boundary rules

1. **Never hand-edit a generated file** (table above). A hand edit is overwritten on the next
   `make bump` and fails the drift gate.
2. **Fix generated output at the source.** Change the generator in `tools/`, then re-run it and
   commit the regenerated output (ideally in its own commit). Commands: `tools/README.md`.
3. Upstream is the source of truth: `opnsense/core` and `opnsense/plugins` at the tag recorded in
   `controllers.json` `meta.core_ref` / `meta.plugins_ref`. Do not "fix" the JSON to match a
   live firewall; bump the refs instead (`make gen-all CORE_REF=<tag>`, which refreshes both
   JSON files; `make bump` alone only refreshes `controllers.json`).
4. Behavior that the registry cannot express belongs in **hand-written** code
   (`states/opnsense.py` tables such as `_RESOLVE_MAP` and `_RECONFIGURE_OVERRIDES`,
   `states/dns.py`), never in the JSON.
5. Hand-written files must not carry the sentinel header; generated Python files must.

## 3. Salt loader and OPNsense API invariants

### Dunder discipline

- Every loadable module defines `__virtual__()` returning `True` or `(False, "reason")`.
  Gate on `utils.common.is_salt_version_ok((3008,))`. Never raise from `__virtual__`.
- `__opts__`, `__pillar__`, `__grains__` are **read-only**. Never assign into them. The only
  mutable shared cache is `__context__` (see `resources/opnsense/__init__.py`).
- Touch `__salt__` **lazily, inside functions** (see `_search_fn()` in `states/opnsense.py`),
  never at import time or module scope. Cross-module calls go through `__salt__["opnsense.*"]`,
  not imports, so per-resource loaders dispatch correctly.
- Execution functions accept `**kwargs` and call `strip_salt_internal_kwargs`, which drops
  `__`-prefixed keys such as `__pub_*`.
- In `resources/opnsense/modules/` and `.../states/` the file location fixes the virtual name:
  do **not** define `__virtualname__` there. Use `__resource__["id"]` / `__resource_funcs__`.
- Ruff already lists Salt dunders as builtins; use `# type: ignore[name-defined]` for type checkers.

### Credential resolution order (`utils/opnsense.py`)

1. **Resources** (preferred): `resources:opnsense:hosts:<id>` pillar via
   `salt.utils.resources.pillar_resources_tree` (`resources/opnsense/__init__.py::_connect`).
2. **Pillar** (non-resource calls, `get_client_from_opts`): the **first** host under
   `resources:opnsense:hosts`, then `opnsense:` (needs `host`) in `opts["pillar"]`, then the same
   two shapes in the `pillar` argument.
3. **Opts / minion config**: `opnsense:` (needs `host`) in `__opts__`.

Grains and proxy configuration are **not** consulted. Do not invent new auth parameters or a new
resolution layer without human review (see section 4). Accepted aliases: `api_key`/`key`/`username`
and `api_secret`/`secret`/`password`. `verify_ssl` defaults to `True`.

### The idempotency bridge (follow all four steps, in order)

1. **Natural key to UUID.** The API mutates by UUID; humans use names/FQDNs. Resolve with
   `search*` (`row_count=-1`) before any write, or via `match` / `_resolve_ref`. Never write
   without knowing whether the item exists. UUID checks use `utils.common.is_uuid`.
2. **Asymmetric payload normalization.** `get*` returns the model wrapped
   (`{"alias": {...}}`) with selection fields as nested maps
   `{"opt1": {"value": "<label>", "selected": 1}, ...}`; `search*` rows are flat; `add*`/`set*`
   expect the model wrapper with **flat** values: a single key or **comma-joined keys** for
   multi-select, booleans as the strings `"0"`/`"1"`, relations as UUIDs. Always compare through
   `diff_models` / `normalize_field_value`, never raw `==`; otherwise every run reports changes
   (state diff loop). Callers pass flat values; the state does not join lists.
3. **Test mode.** If `__opts__["test"]` is true, issue no `add`/`set`/`delete`/`reconfigure` and
   return `{"name": name, "result": None, "changes": {...}, "comment": "..."}`. When there is
   nothing to change, return `result: True` with empty `changes`.
4. **Two-phase commit.** OPNsense stages config; only `reconfigure` applies it. Call the service
   reconfigure endpoint **only when a mutation actually happened** (`changes != {}`), once per
   state (batch states pass `reconfigure=False` per item, then reconfigure once). A failed
   reconfigure makes the state `result: False`.
- Keep the return dict shape `{"name", "result", "changes", "comment"}`; `result` is
  `True | False | None`.
- Reconfigure endpoint tables exist in two places (`utils/common.py::RECONFIGURE_DEFAULTS`,
  used by `states/dns.py`; `states/opnsense.py::_RECONFIGURE_DEFAULTS` /
  `_RECONFIGURE_OVERRIDES`, used by the generic states). Update both if you change one;
  do not add a third.
- Do **not** add savepoint/auto-rollback to `opnsense.reconfigured`; upstream removed it.
  See `docs/FIREWALL_SAFETY.md`.

## 4. Scope and governance boundaries

**Allowed autonomously:**
- Unit tests with mocked transport or `__salt__` fixtures.
- Fixing generator templates in `tools/`, then regenerating (with the drift check green).
- Improving state idempotency; fixing diff/normalization bugs with a regression test.
- Docstrings, type hints, `TypedDict`s, docs under `docs/`, changelog fragments.

**Human gate required (open the PR, flag it, do not merge or self-approve):**
- `pyproject.toml` dependencies, `requires-python`, or `salt` version floor.
- Any change to GitHub Actions, especially `.github/workflows/publish.yml` (release pipeline).
- Authentication, credential-resolution, secret-masking, or SSL-verification defaults
  (`OPNsenseClientConfig.verify_ssl`, `_SENSITIVE_*`, `get_client_from_opts`).
- Bumping the OPNsense `core_ref`/`plugins_ref` (changes the public API surface).
- Running any test against a real firewall (`tests/integration`, `OPNSENSE_LIVE_TEST=1`).

Never commit real hostnames, IPs, or credentials; use `example.com` and RFC 5737 addresses.
`tools/check_public_boundary.py` hard-fails CI on private strings.

```bash
pre-commit run --all-files                 # mirrors .github/workflows/lint.yml
```

Equivalents: `nox -s lint`, `nox -s tests-3.12`, `make test`, `make lint`.
After touching a generator or bumping refs, also run the network check:
`nox -s codegen_drift` (re-generates from upstream and compares; see `tools/README.md`).

Unit tests are **offline-first**: `tests/conftest.py` fails any test that opens a non-loopback
socket or sends through `requests`. Mock `requests.Session.request` or `__salt__`. Mark a test
`@pytest.mark.allow_network` only for opt-in live tests.

Add a towncrier fragment for user-visible changes: `changelog/<yyyymmdd>.<type>.md`
(types in `pyproject.toml` `[tool.towncrier]`).
